03 / Working method

Documentation as engineering.

How I approach technical content that must remain accurate, scalable, and useful to people and agents.

01 / UNDERSTAND

Start with the product.

Read code, follow the API, reproduce the workflow, and establish what developers actually need to do.

02 / STRUCTURE

Make context explicit.

Use stable headings, clear inputs and outputs, canonical links, examples, and machine-readable metadata.

03 / VALIDATE

Test before publishing.

Review examples, examine edge cases, use Git-based checks, and require citations where agents retrieve documentation.

04 / MAINTAIN

Reduce documentation drift.

Automate repeatable analysis, connect reviews to engineering changes, and measure what users cannot find.
