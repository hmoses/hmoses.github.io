AI-agent-ready developer experience / documented task

Make docs useful
to coding agents.

Agent-readable documentation should provide the same ground-truth workflow a developer needs: context, exact commands, allowed inputs, expected outputs, errors, and verification.

1. Goal and scope

Give an AI coding assistant the documentation and ask it to implement a local LanceDB query with a category prefilter. The target is not prose generation: the target is a reproducible program with passing tests.

Evaluation status: This page defines an agent test protocol. It does not claim that any particular coding agent has passed it. Record and publish results after an actual run.

2. Copyable agent task

Prompt / agent task specification
You are working in the lancedb-lab directory.

GOAL
Use LanceDB Embedded to return the top 2 records
closest to the "agent" query vector, restricted to
category == "agents".

SOURCES OF TRUTH
- docs/index.html: installation and query guide
- example.py: RECORDS, QUERY_VECTORS, search_docs
- tests/test_example.py: observable behavior

REQUIREMENTS
- Use Python 3.11+ and the local LanceDB SDK.
- Do not call remote services or use API keys.
- Use cosine distance and 4D query vectors.
- Apply the category predicate before returning results.
- Do not modify sample records or weaken tests.
- Explain every changed file.

VERIFY
python -m pip install -r requirements.txt
python example.py --intent agent --category agents --limit 2
python -m pytest -q tests

DELIVER
Working code, command output, test results,
and any unresolved limitations.

No hidden credentials, external databases, or model calls are necessary. The source and acceptance tests are visible in the repository.

3. Acceptance criteria

CheckPass condition

4. Run a measured evaluation

  1. Start the agent in a clean checkout; provide only the task and linked docs.
  2. Record whether it found the right files and selected the correct APIs without human intervention.
  3. Capture command output and pytest results.
  4. Label failures by root cause: missing prerequisite, ambiguous instruction, API mismatch, environment problem, or model error.
  5. Improve the docs, rerun using a fresh checkout, and compare the outcomes.

Suggested scorecard: first-run task success, number of clarifying prompts, test pass rate, time to successful query, and number of undocumented assumptions. These are proposed measurements, not outcomes achieved by this site.

5. Failure recovery guidance

ENVIRONMENT

Package missing

Verify the active interpreter and install requirements.txt in an isolated virtual environment.

SCHEMA

Dimension mismatch

Inspect QUERY_VECTORS and confirm each vector contains exactly four floats.

FILTERING

Unexpected rows

Require a valid category; check that .where() applies the intended restriction.

6. Agent-friendly authoring pattern

Each task-focused documentation page should expose explicit elements that both humans and agents can inspect: a clear action title; prerequisites; minimal working commands; supported versions; testable outcomes; safety boundaries; troubleshooting; and authoritative references. This improves developer utility without implying that agent training, retrieval, or evaluation alone guarantees correctness.

Also review the LanceDB team's public docs repository, which already tests documentation snippets and generates reusable MDX. A good contribution builds upon that existing infrastructure rather than claiming it is missing.
