LanceDB Developer Lab / independent portfolio / optional hosted integration

Vector search finds candidates. Jev finds better answers.

LanceDB first retrieves passages with similar embeddings. Jev, TypeSafe's question-aware reranker, can evaluate whether each shortlisted passage actually helps answer the user's question, then change the ranking.

Important boundary: The exercise below uses invented sample scores to teach the concept. It does not invoke LanceDB or the Jev API. The separate jev_example.py integrates LanceDB's native TypeSafeReranker and calls TypeSafe's hosted service, so it requires a compatible SDK revision, connectivity, a TypeSafe API key, and potentially usage credits. The original local lab still needs no key.

Pipeline: question → embedding → LanceDB retrieves 8 candidates → Jev checks relevance against the actual question → return 3 reranked answers. Jev cannot promote a relevant document if it is missing from the retrieved candidate set.

      3. Integrate Jev into the LanceDB query

      The real program reuses this lab's eight sample records and four-dimensional query vectors, then sends the question text and matching document text to the hosted reranker. For production retrieval, replace these hand-authored vectors with embeddings from an appropriate model.

      Python / core native integration
      from lancedb.rerankers import TypeSafeReranker
from example import QUERY_VECTORS, create_table

reranker = TypeSafeReranker(
    model_name="jev-1.13.0",
    column="text",
    api_key=api_key,
    instructions="Is the document relevant to the query?",
    criteria={
        "true": "The document helps answer part of the query.",
        "false": "The document is unrelated or only shares keywords.",
    },
    batch_size=40,
    max_concurrency=4,
)
# After the full script creates table, use an eight-candidate pool:
reranked = (
    table.search(QUERY_VECTORS["vector"])
    .distance_type("cosine")
    .limit(8)
    .rerank(reranker, "How can I diagnose vector dimension errors in LanceDB?")
    .to_list()
)[:3]
for row in reranked:
    print(row["title"], row["_relevance_score"])

      Run the complete Python file rather than this excerpt alone. The full file reads the secret from the environment, creates a disposable local database, retrieves a common candidate pool, and compares original and reranked positions.

      4. Understand the Python, line by line

      1. TypeSafeReranker imports LanceDB's built-in adapter for TypeSafe's Jev service.
      2. column="text" identifies the field containing each candidate document's passage.
      3. instructions and criteria specify what relevant means. Their wording is a model parameter to evaluate, not a guarantee.
      4. table.search(query_vector) finds vectors close to the query; the sample vectors already exist, so this demo does not generate embeddings.
      5. .distance_type("cosine") selects cosine distance for the retrieval stage. Smaller distance means closer vectors.
      6. .limit(8) chooses eight candidates to send to Jev. Set it high enough to include likely evidence without paying to score too many irrelevant passages.
      7. .rerank(reranker, question) asks the hosted service to judge those candidates against the actual user's question.
      8. _relevance_score is Jev's score. It is not the same quantity as LanceDB's _distance.
      9. [:3] selects the top three after reranking, rather than limiting to three before Jev can reorder them.

      5. Is Jev better than plain vector search?

      Sometimes, not always. In LanceDB's September 2026 evaluation, reranking with a broader Jev relevance prompt improved hybrid retrieval on several datasets, but some rerankers degraded strong vector baselines. The result depends on the domain, relevance rubric, candidate pool, latency, and cost. Test with queries and labeled answers from your documentation.

      MeasureWhat to test
      Recall@20Does LanceDB retrieve the needed passage before reranking?
      Hit@1 / nDCG@5Does Jev place useful evidence earlier?
      p50 / p95 latencyHow much end-to-end response time does the hosted API add?
      Cost / errorsHow many rerank requests, retries, and credits per question?
      GroundingCan a user find source passages that support the generated answer?

      Keep a baseline without reranking and compare it with Jev using the exact same candidates. Prompt instructions and thresholds must be validated on held-out queries; no benchmark statistic guarantees better performance in every deployment.

      6. Troubleshoot

      • ImportError for TypeSafeReranker: Your installed LanceDB version may not contain the integration. Follow the official pinned benchmark dependencies.
      • Missing key: Set TYPESAFE_API_KEY securely; do not paste it into the web tutorial or a GitHub file.
      • 401, 429, or network failure: Verify credentials, quotas, service status, and retry policy. Do not silently present the baseline as Jev output.
      • Results do not improve: Review the question's wording, the candidate pool, ground-truth labels, and whether the vector search retrieved the answer at all.
      • Extra latency: Reduce the candidate pool only after measuring its effect on recall. Measure the full pipeline, not the reranking stage alone.
