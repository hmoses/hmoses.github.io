02 / Proposed Render workflow

Content as a measurable system.

A candidate operating model grounded in the job description, not a claim that I have built or deployed a workflow inside Render.

01 · DISCOVER

Find citation and answer gaps

Sample developer and agent queries. Record whether sources are correct, absent, outdated, or cited from competitors. Combine qualitative review with analytics.

02 · PRIORITIZE

Build a defensible backlog

Score each gap by developer value, topical fit, measured visibility, technical source readiness, and expected maintenance load.

03 · PRODUCE & VERIFY

Use AI where it helps

Generate briefs and source-backed drafts; validate commands, APIs, version assumptions, and links. Require expert approval for product claims.

04 · MEASURE & REFRESH

Keep content accurate

Track citation quality, assistant referral sessions, conversions, search discovery, content age, and product changes. Feed failures into the next sprint.

What I would test before scaling a content factory

Source fidelity: every factual claim links to a current product document or reproducible test. Developer utility: a reader can complete the task with stated prerequisites and expected results. Agent retrieval: the correct canonical page is returned for a representative question. Refresh triggers: product changes produce an actionable content review. Metrics: citation presence, accuracy, qualified sessions, and signups are evaluated separately from publishing volume.

Implementation principle: build a traceable pipeline from question → evidence → brief → draft → validation → publish → evaluation → refresh. Render Workflows is a product technology I would learn and use in this role; no previous production Render Workflows deployment is claimed.
